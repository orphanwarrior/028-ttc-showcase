# 开发中遇到的几个问题

这里记几个稿子生成以后会遇到的问题，当前代码里都有对应处理。关于固定工作流和 Agent 怎么调整，另外写在[产品设计记录](PRODUCT_CASE_STUDY.md)里。

## 通过校核的是哪一版

第一版检查通过了，之后又改了正文，旧报告当然不能继续算数。但程序如果只记一个“已通过”，这件事就很容易漏掉。

现在报告会带着草稿修订号和 SHA-256 内容指纹。用报告前先核对它对应哪份稿子，改过正文就不能沿用原来的结论。代理师再确认具体版本，后续阶段读取这份确认内容。

这样改稿以后可能要重新检查，处理也多了一些。至少回头看时，能知道当时查过的究竟是哪一版。内容指纹只能核对是否同一份内容，稿子写得对不对还要审核。

## 等模型返回时，前面的内容可能已经改了

生成说明书时可能要等几分钟。这期间如果用户又改了权利要求，模型返回的还是按旧稿写的内容，直接放进当前版本就会对不上。

所以开始时记下输入版本，生成结束准备发布时，再核对一次。模型调用放在数据库事务外，最后切换版本才用短事务处理。发现输入变了，就保留这次结果，但不把它直接当作当前稿。

这意味着有时已经花了调用费用，结果却不能直接用。不过也不能因为钱已经花了，就让用户接着处理一份依据过期的稿子。

附图还得分开看：部件关系和技术内容变了，会影响说明书；只是移动位置、调整排版，经过检查可以保留原来的说明书，没必要全部重写。

## 重新生成失败，原稿还得在

上一版可能已经人工改了很久。点一下重新生成，新任务失败了，原稿也没了，这个结果很难接受。

现在新任务单独保存草稿、调用和校核记录，检查通过、输入也没变化，再切换当前版本。失败尝试留在历史里，用户可以继续改原稿。

记录会多一些，界面也要把当前稿和失败尝试分清楚。已有草稿可以继续拿来处理，但还做不到从模型中断的那个位置原样接着生成。

## 允许返工，也得有个结束的时候

模型没写好就立即结束，有些能修的问题会被放弃；一直让它改，又可能等很久、花很多调用，最后仍然没有结果。

目前允许在任务范围内查材料、改稿和独立校核，同时限制调用次数、用量和时间。附图与实施例任务默认最多六次调用、九万个已报告的模型用量单位（Token）、240 秒。这个设置也考虑了我自己承担的接口费用。

关键事实缺了就问人，用户取消或达到限制就停，已有草稿留下来。接口不会自动把整次任务重新跑一遍，是否再试由用户决定。

用量也不是供应商总能完整返回的，未知部分会另记。单次调用的消耗可能超过预估，所以这些限制还不能当成精确的费用封顶。

相关回归检查过旧报告失效、输入变化、原稿保留、取消和预算停止。它们检查的是这些处理有没有执行到，生成内容的专业质量还要另外看。完整范围见[验证记录](VALIDATION.md)。
